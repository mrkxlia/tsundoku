# コードから仕様書を逆生成するWebアプリ「cc-rsg-web」を公開しました
2026-08-11
## はじめに

こんにちは、daishir0です。  
普段はClaude Codeを趣味と開発でガシガシ使っていて、副産物として小さなシステムをいくつか公開しています。GitHubは [こちら](https://github.com/daishir0) です。

以前、 [Claude Code Skill「cc-rsg」をWeb化した話 — OpenHandsという発見](https://zenn.dev/daishiro/articles/openhands-cc-rsg-webapp) という記事を書きました。その後も手を動かし続けていて、ようやく外に出せる形になったので紹介させてください。

`cc-rsg-web` という、コードベースから仕様書を「逆生成」するWebアプリを一般公開しました。

正直なところ、レガシーなコードに仕様書が無い、という現場はめずらしくないんですよね。作った人はもういない、ドキュメントは散逸している、コードだけが残っている。「読めないコードを、引き継げる資産に」というのが、このプロジェクトの出発点です。

## cc-rsg-web とは

ざっくり言うと、コードベースをアップロードすると、AIが仕様書のたたき台を自動生成してくれるWebアプリです。

土台にしているのは、OSSとして公開している [cc-rsg](https://github.com/daishir0/cc-rsg) （リバース仕様書ジェネレータ）です。 `cc-rsg-web` は、その cc-rsg をブラウザから使えるようにしたもの、という位置づけになります。

ポイントは「コードを読むだけ」では終わらないところです。コードからは読み取れない設計判断の理由や、例外処理の経緯みたいな「現場の頭の中にしかない情報」を、AIとの対話で引き出して仕様書に織り込んでいきます。

そもそも、コードの中には存在しない情報って、けっこうあるんですよね。背景や目的、なぜこの実装にしたのかという理由、性能やセキュリティといった非機能要件。このあたりは、よく知られている通り、たいてい人間の頭の中にしかありません。

だとすると、AIに仕様書を完璧に書かせる、というのはそもそも無理があります。コードに書いていないことは、コードからは出てこないので。かといって、人間が一から全部を書き起こすのは、現場の感覚としてかなりしんどい作業です（みんな、ここで力尽きますよね…）。

なので、AIが拾えるところは拾い、人間しか知らないところは対話で足していく。AIと人間で協調しながら仕上げていく、というアプローチは、わりと現実的で妥当なんじゃないかと思っています。cc-rsg-web は、そういう思想で作っています。

## 6フェーズで進む

cc-rsg-web は、生成プロセスを6つのフェーズに分けています。AIに丸投げするのでも、人間が全部書くのでもなく、役割分担をはっきりさせている、という感じです。

| フェーズ | 内容 | 主役 |
| --- | --- | --- |
| Phase 0 | Setup & Goal（ゴール定義5問） | 人間 |
| Phase 1 | Recon（浅い偵察・テンプレ提示） | AI |
| Phase 2 | Plan & WBS（分割・インベントリ抽出） | AI |
| Phase 3 | Investigate（並列調査＋REF付与） | AI |
| Phase 4 | Verify（照合・整合性検証） | AI |
| Phase 5 | Dialogue（対話で暗黙知を回収） | 人間 ↔ AI |
| Phase 6 | Deliver（Markdown納品） | AI |

特に効いてくるのが Phase 0 と Phase 5 です。

- Phase 0（ゴール定義）: 「誰が・何のために読む仕様書か」を5つの質問で最初に決めます
- Phase 5（対話）: AIが章ごとに「この設計判断の理由は?」と質問してきて、こちらは答えるだけ。回答が本文に反映されます

この2つのフェーズで、作る側の意図とドメイン知識をAIに注入する、という設計です。サイトにはこの流れを1枚の図にして載せているので、見てもらった方が早いかもしれません。

## 実証：Redmine を解析してみた

「で、実際どのくらいのものが出るの?」が一番気になるところだと思います。

実証として、OSSの Redmine（Ruby、約35万行）の全体を解析させてみました。

- 1,095 Ruby ファイル / 約35万行を対象
- 約90分で叩き台を生成
- 13章 + マニュアル、約5,000行の仕様書
- Mermaid図（ER図・シーケンス図など）と、ソース行への参照（REF）つき

![cc-rsg-web の生成完了画面。全フェーズ完了後、左に成果物（13章）の一覧、右に章のプレビューが表示される](https://static.zenn.studio/user-upload/deployed-images/418d21efad64fe68f1d9d50f.png?sha=a3b43dcab1164eb86a810d3895a324892b2bbe02)

人手・AI丸投げ・cc-rsg-web を並べると、こんな整理になります。

| 観点 | 人手 | AI丸投げ | cc-rsg-web |
| --- | --- | --- | --- |
| 所要時間 | 数週間〜数ヶ月 | 数時間 | 数時間〜数日 |
| 正確さ | 高い | 低い（幻覚あり） | 高い（REF検証つき） |
| 暗黙知の取り込み | 高い（属人的） | 不可 | 高い（対話で引き出す） |
| 追跡可能性 | 低い | なし | 高い（REF全文） |

AI丸投げの弱点は、それっぽいけど根拠が無い文章が混ざるところなんですが、cc-rsg は全文にソース参照（REF）を強制で付けるので、「この記述はどこ由来か」を後から追えるようにしています。

## サイトの見どころ

ランディングページ自体に、実際の生成物を載せています。

実証ケースのセクションでは、Redmineの仕様書13章を、その場で章ごとに切り替えて読めるようにしました。Mermaid図はクリックすると拡大できて、ドラッグ移動やホイールでのズームもできます。

![サイト上で、生成された仕様書13章を切り替えながらその場で閲覧できる。画像はログイン処理のシーケンス図](https://static.zenn.studio/user-upload/deployed-images/4f0d8d7fec076550c57268ee.png?sha=0b850d86b9df63bb554bf123069c6568b957c878)

見てもらうと分かるのですが、これは「AIが完璧な仕様書を書いてくれた」という類のものではありません。あくまで土台、たたき台です。正直、足りないところや、推測で埋めている箇所もあります。ただ、ここがスタートラインで、cc-rsg-web の中で対話を重ねながら、自分にとって理想的な成果物に仕上げていける、というのがこのツールの肝なんですよね。「AI単独でここまで」ではなく「ここから一緒に育てていく」もの、と思ってもらえるとしっくりくるかもしれません。

## 学術的なチャレンジ

手法そのものは、学術プレプリントとして Zenodo で公開しています。

> A Phased Co-Construction Methodology for Reverse Specification Generation: Why AI-Native Documentation Requires the Human  
> [https://zenodo.org/records/20541685](https://zenodo.org/records/20541685)

とはいえ、これはあくまでプレプリント（査読前の公開）であって、何かが学術的に裏付けられた、というものではありません。「AIネイティブなドキュメント生成に、なぜ人間が必要なのか」という問いを、できれば学術的な観点からも貢献できる形にしていきたい、というチャレンジの途中、という位置づけです。
